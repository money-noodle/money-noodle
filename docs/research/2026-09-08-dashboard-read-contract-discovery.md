## Parity questions (priority order)

1. **P0 — baseline binding:** establish attributable deployed artifact/revision and permitted observation before parity claims.
2. **P0 — browser work/refresh:** historical polling and `refresh=live` appear to invoke live venue/oracle assembly through a browser-triggered route. Define API-owned bounded read-model/refresh authority and idempotence; this is a parity question, not accepted v2 behavior.
3. **P0 — time/freshness contract:** separate response generation, upstream observation, fetch and render time; set maximum-staleness behavior per projection and make cache-layer ownership explicit.
4. **P0 — paper-only clarity:** preserve no-inferred-empty results, paper/live separation, and no public accounts/controls.
5. **P1 — threshold semantics:** preserve exact-hour selection, distinct strike YES semantics, missing-ask/ambiguity unavailable behavior.
6. **P1 — public authorization:** define any future public projection and tenant scope independently; absence of an inspected check is not authorization design.
